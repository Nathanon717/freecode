# Every Mistral model 400s mid-session on an empty assistant message

**Symptom:** all Mistral models threw
`Mistral HTTP 400 Bad Request: {"message":"Assistant message must have either
content or tool_calls, but not none.","code":"3240"}`.

**Cause:** `Conversation.addAssistantMessage` pushed the turn's text
unconditionally (`command-dispatcher.ts:130` passes `result.text` straight
through). A turn that ends with no final text — a tool-only step, an abort, an
empty completion — stores `{ role: 'assistant', content: '' }`. Mistral rejects
any request whose history contains an assistant message with neither content nor
`tool_calls`, so one such turn breaks *every* later request in the session,
regardless of model. Not a request-transform bug: the offending message is the
tail of freecode's own history, not something the AI SDK emits mid-turn (its
interior assistant messages always carry `tool_calls`).

Confirmed against the live API: `[user, assistant(''), user]` → 400 code 3240;
the same triple with non-empty assistant text → 200; and `[user, user]` → 200,
so dropping the message is safe.

**Fix:** `addAssistantMessage` ignores blank/whitespace-only content. An empty
assistant turn carries no information, and the resulting consecutive user
messages are accepted: verified live against Mistral, and the Anthropic path
goes through `@ai-sdk/anthropic` (`adapters/anthropic.ts:236`), whose message
conversion merges consecutive same-role turns before they reach the API.

**Coverage:** `tests/agent/conversation.test.ts` — "drops empty assistant turns".
