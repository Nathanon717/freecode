# 29-07-2026 — The post-wipe transcript replay looked nothing like a transcript

## Symptom

[27-07-2026c.md](27-07-2026c.md) stopped `/config`, `/model` and `/eval` from
leaving a live session looking fresh, by reprinting the conversation after the
wipe. What came back did not resemble what had been on screen:

- assistant text arrived raw, never through `renderMarkdown` — headings, bold,
  code fences all as literal syntax;
- no step dividers at all, so turns ran together;
- tool result bodies omitted entirely, deliberately;
- `edit` and `create` reduced to a bare call line, no diff, no created content;
- the `> ` prompt echo dimmed, where the live one is banner-coloured, and
  continuation lines of a multi-line prompt not indented.

## Cause

Two separate things, and only the second is really a bug.

**The renderer was never the problem.** `renderTurn(steps: RenderedStep[])` has
been a pure data-in API all along, and `commands/renderer.ts` already drove the
entire transcript look from static data with no involvement from `agent/loop.ts`.
`transcript-replay.ts` simply did not use it — it imported exactly one symbol,
`formatToolCallLine`, and hand-rolled everything else.

**Rendering from `Conversation.messages` cannot be faithful.** History stores a
tool's result *string*, not the `oldText`/`newText` that `formatEditFileDiff`
renders from. So no amount of adapter work gets an edit diff back: the
information is not in the object being rendered from. This is the part that
forced a different mechanism rather than a better adapter.

## Fix

Record what was rendered, replay that.

`cli/render/transcript-record.ts` is an append-only, size-capped record of what
the renderer put on screen. The hooks live *inside* the renderer —
`writeToolCallHeader`, `writeToolResultPreview`, `writeToolStepResult`,
`writeTranscriptText` and `endTranscriptStep` all record as a side effect — so
any caller rendering normally is recorded automatically and the two cannot drift.
Prompts come from `session-modes.ts`; the fake provider records its own chunks.

`replayTranscript` then walks the record and hands each turn straight back to
`renderTurn`. Same formatter, same inputs, same output. The unit test asserts
this directly rather than by proxy: it captures the live paint, replays, and
requires the two byte strings to be equal.

Three details that decided the design:

- **Tool bodies are stored already-rendered** (`ToolStepResult`'s new
  `preformatted` kind). Storing the raw result would be unbounded — the preview
  is capped at `maxResultLines`, the result behind it can be megabytes — and
  re-rendering a clipped copy would change the `... (N more lines)` count. The
  rendered block is both bounded and exact.
- **Tool headers stay structured**, so a replayed call line still comes from
  `formatToolCallLine` and cannot drift from the live one.
- **Ephemeral UI is not recorded.** Menu chrome, approval prompts and retry
  countdowns rewrite themselves with cursor motion; replaying those escapes would
  scribble. The record holds the conversation only.

`writeTranscriptText` (write + notify state machine + record) replaced the
`process.stdout.write` + `notifyTranscriptChunk` pairs in `loop.ts`,
`parsed-tools.ts` and `fake-loop.ts`, which is also what fixed the raw-markdown
replay: `parsed-tools.ts` had been notifying with the *unrendered* text while
writing the rendered text.

`formatPromptEcho` is now shared between the live input UI and the replay, so the
echo cannot drift again. `/clear` clears the record alongside the history —
without that, `/clear` lands on a bare banner and the next `/model` resurrects the
cleared conversation.

**The module-global `_step` state machine.** A replay drives it too, so it
brackets itself with `resetTranscriptTurnState()`: a clean slate first, or the
first replayed turn opens with the divider the last live turn deferred; then
`resetTranscriptTurnState(true)` after, leaving the machine exactly as a completed
turn would. Recording is suspended throughout, or the replay appends itself to
the record it is reading.

**Kept from the old implementation:** the `Conversation history (N messages, still
sent to the model)` header. The record is what was *on screen*; the history is
what is *sent*, and stating the latter is the whole point of the original fix.
The old `MAX_REPLAYED_MESSAGES` tail-trim is replaced by the record's size cap,
reported as `… N earlier entries not shown`.

**Rejected: tee the bytes.** Byte-exact and conceptually trivial, but it moves the
work into classifying all 59 `process.stdout.write` sites as permanent-transcript
or ephemeral-chrome, and one wrong call replays a cursor-up into a context where
it scribbles. Every future write site is another chance to get it wrong.
Recording structured steps costs a little exactness on paper and none in practice,
and it reflows correctly when the terminal is resized inside the menu.

## Coverage

- `tests/cli/render/transcript-replay.test.ts` — live paint vs replay, byte for
  byte, for a text+tool turn, an edit diff, and a truncated long result. Plus
  prompt echo, multi-line indent, the header count, replay-not-recorded, and
  divider placement across two turns.
- `tests/cli/render/transcript-record.test.ts` — turn/step grouping, chunk
  accumulation, result attachment and overwrite, orphan results dropped, an
  error-abandoned turn closed by the next prompt, suspension, cap eviction, and
  the open turn never being evicted.
- `tests/cli/render/transcript-renderer.test.ts` — `writeTranscriptText`'s three
  effects, deferred-divider behaviour, and `resetTranscriptTurnState` both ways.
- `tests/e2e/tty-config-keeps-transcript.e2e.json` — the fixture now takes a turn
  with a preamble, a `create` call and a final answer, and asserts all of it comes
  back after `/config`: the text, `create(magic.txt)`, and the created-file
  preview under it. Needs `config.toolConfirmation: "auto"` — the
  `FREECODE_AUTO_CONFIRM` env var alone leaves the approval prompt blocking the
  turn.

## Side effect

`transcript-renderer.ts` went over the 500-line limit, so the pure formatters
moved to `cli/render/transcript-format.ts` (re-exported, so callers keep importing
from one place). That is a real seam: one module decides how things *look*, the
other owns the state machine and the writing.
