# Every documented interface, type alias and enum lost its doc comment on the way to its map page

**Files:** `scripts/docgen/map-exports.ts`

The generated `Exports` block printed interfaces, type aliases and enums with
their bodies but never their own documentation — so `ModelDataMap` reached
`docs/map/store/db-types.md` as a bare `type ModelDataMap = Record<string,
ModelEntry>` while the source said what the keys are. Functions, classes and
consts were unaffected. Silent: the page looked complete, just less useful than
the source it was generated from.

**Cause:** `renderSymbol` has a branch for those three kinds that emits
`decl.getText()` verbatim, on the belief — written down in `docComment`'s own
header — that they "keep their documentation for free". They do not.
`Node.getText()` starts at `getStart()`, which skips leading trivia, and a
JSDoc comment is leading trivia. The claim was never tested, and the one file
that appeared to confirm it (`providers/model-quirks.ts`) has a documented
first export, so its output looked right for an unrelated reason.

Probed directly, the two routes disagree, which is the whole bug:

```
getText():    "export interface Foo { a: string }"
getDocumentationComment(): "Doc on the interface."
```

**Fix:** prepend the lifted `doc` in that branch, once for the merged group
rather than per declaration, and correct the comment that asserted otherwise —
the false claim is half the defect. Nothing carries documentation across on its
own: the checker reports a signature, `getText()` starts below the comment, so
every branch of `renderSymbol` has to lift it back deliberately.

`npm run docs:generate` then added the missing docs to 17 pages.

**Found by:** probing whether a module header comment attaches to the following
export (it does, blank line or not) while preparing `@role`/`@readwhen` — which
is also why tags must never be lifted here: a lifted `@role` would print the
page's own Role inside its Exports.
