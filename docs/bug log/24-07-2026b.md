# PTY test harness on Windows: resize test skipped (nested ConPTY limit); session `start` deadline hardened

**Files:** `tests/harness/pty/session.ts`, `tests/harness/pty/session.test.ts`, `tests/harness/pty/driver.test.ts`

Same commit was green on Linux but `npm run pty:test` showed 6 failures on Windows: `start`/`screen`/`send`/`stop` in `session.test.ts` (cascading from `start`) and the resize test in `driver.test.ts`.

1. The `resize delivers SIGWINCH...` test spawns a driver (real PTY) whose child process is *itself* PTY-hosted via ConPTY — a nested-ConPTY scenario. Confirmed directly against `node-pty`'s `resize()` (bypassing the test/driver entirely, with and without `useConptyDll`) that Windows never delivers a `process.stdout` `resize` notification to the grandchild in this configuration; matches documented Node/ConPTY limitations. Not reproducible as a real-usage bug — an actual interactive freecode session isn't nested this way. Skipped on `win32` rather than "fixed", since there's nothing in `driver.ts` or `src/` to change. This one is confirmed.

2. The `start`/`screen`/`send`/`stop` failures could **not** be reproduced in this environment — `session.test.ts` passed both standalone and under a full `npx vitest run` (113 files, same command/load that produced the original 6-failure report). While investigating, found a real latent budget mismatch worth hardening regardless: `cmdStart`'s client-side ready-poll deadline (20s) is tighter than the daemon's own worst-case startup budget — `waitForText('for commands', 20_000)` + `settle(400)` + the up-to-40-iteration input-liveness probe (~150ms×2 per iteration, added in [02-07-2026.md](02-07-2026.md) for Windows ConPTY lag) can legitimately exceed 20s. Widened the client deadline to 40s and the corresponding `spawnSync`/vitest test timeouts (`session.test.ts`) to match. This reduces the chance of a repeat, but the original 5 failures were never actually caught in the act — treat as hardening, not a confirmed fix. If they recur, get a `pty:test`-in-a-loop repro before trusting any diagnosis.
