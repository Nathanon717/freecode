# Bug Log

## Blocklist-purge prompt returns on every launch, no matter how often you delete

**Symptom:** On every launch the "N stored models are now blocklisted … Enter to
delete" prompt reappears for the same models (e.g. `anthropic:claude-opus-4-1-20250805`
and `openrouter:nvidia/nemotron-3.5-content-safety:free`). Pressing Enter deletes the
rows, prints "Deleted N models.", and yet the exact same prompt is back next launch.

**Cause (`src/providers/provider-registry.ts`):** the purge delete worked fine — the
rows were re-created immediately afterwards. `runLiveProviderInit`'s `finish()` wrote
the DB catalog (`saveProviderCatalog`, inside the function) straight from
`selectModels(fetched)`, and blocklist filtering was *not* centralized there:

- **Registry blocklist** was only applied by the *individual* `selectModels` of some
  providers. openrouter's `selectModels` filters to `:free` only, so its
  `modelIdBlocklist` (which lists `nvidia/nemotron-3.5-content-safety`) never touched
  the catalog write — that model earned a fresh row every launch.
- **User blocklist** was stripped in `_doInit` (lines ~44–55) only *after* the
  `Promise.all` that runs live init — i.e. after live providers had already written
  their catalogs. anthropic has no registry blocklist and its `selectModels` returns
  everything, so a user-blocklisted `claude-opus-4-1` came right back.

The comment at `_doInit` even claimed the user-blocklist strip runs "before any catalog
is written" — true for static providers (catalog written later in `_doInit`), false for
live ones.

**Fix:** apply both blocklists centrally in `runLiveProviderInit`'s `finish()`, before
`saveProviderCatalog` and before the picker sees `entry.models`: the registry
substring + exact blocklist and the user blocklist. Idempotent for providers whose
`selectModels` already filtered. The `_doInit` strip stays (still needed and correctly
ordered for static providers); its comment was corrected.

**Note:** the fix stops re-creation but does not delete rows already in the DB, so the
prompt shows **one last time** on the first post-fix launch (purge check runs before the
warm), then never again once Enter clears the stale rows.

**Coverage:** `tests/providers/provider-registry.test.ts` — "openrouter drops
registry-blocklisted ids from models and the catalog write" and "anthropic drops
user-blocklisted ids from models and the catalog write", both asserting the id is absent
from `entry.models` and from the `saveProviderCatalog` argument.
