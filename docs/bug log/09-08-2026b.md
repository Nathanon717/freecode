# A map section ran past the end of its own generated block, absorbing the prose below it

**Files:** `scripts/docgen/map-sections.ts`, `scripts/docgen/generate-docs.ts`

`parseMapPage` ended an H2 at the next H2 and nowhere else, so the last section
inside a generated block swallowed everything written under the block's closing
marker. On `cli/render/banner.md` that made a paragraph about `startOverlayEpoch`
part of `## Role` — and `Role` is the section `npm run map -- role '**'` pulls
across all 115 pages at once, so the mis-attribution would have been paid for on
every bulk query. It also hid the page from the orphan-prose audit that exists to
find exactly that text.

**Cause:** a generated block is a boundary the parser did not know about. It
dropped `BEGIN`/`END GENERATED` marker lines so they would not appear inside a
body, which made them invisible as terminators too.

Latent until the `Role` block moved to the top of the page: while the only
authored prose sat *between* two H2s it had a next-heading to stop at. The
symptom count went 12 orphan pages → 1 → 12, and the middle number is the bug.

**Fix:** a section stops at the next heading **or the next generated marker,
whichever comes first**. Prose under a block is orphan prose again — visible to
the audit, absent from `Role`.

Alongside it, `upsertIntentBlock` now cuts and re-lays the block under the page's
H1 rather than replacing it where it sits. Position becomes a property of the
generator instead of wherever the block first landed, which on the 12 pages
opening with a legacy inline field was below it — a page introducing itself with
something other than what its module is for.

**Verified:** all 115 pages open with `Role`; the orphan-prose list is back to
the 12 the overhaul had already counted, with no page added or lost.
