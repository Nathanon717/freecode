# 30-07-2026 — Markdown headings were swallowed whole; now they render bold

## Symptom

A model that wrote `## The plan` put nothing on the screen. Not unstyled text —
nothing. The heading's words were lost, and the reader saw only the blank line
that followed it.

## Cause

`markdown-renderer.ts`'s line processor had a single line for headings:

```ts
if (/^#{1,6}\s/.test(line)) return null;
```

`null` is the processor's "drop this line" signal (used legitimately for fence
delimiters and buffered table rows), so the whole line was consumed with nothing
substituted. Every other construct in the renderer strips its markers and keeps
its text; headings were the one that took the text with them.

Scope worth stating precisely: the drop only ever happened when markdown
rendering was **active** (`process.stdout.isTTY || FORCE_COLOR`). Piped without
`FORCE_COLOR`, `createMarkdownStreamRenderer` returns a pass-through and
`## The plan` arrived literally — so the words vanished exactly in the
interactive case where a model is most likely to write a heading.

## Fix

`renderHeading` strips the `#` markers and any closing run (`## Foo ##`), runs
the remainder through `renderInline` so a code span or `**bold**` inside the
heading survives, and wraps the result in `chalk.bold` + `wrapStyled`. All six
levels render identically — the terminal has one weight to spend.

The `\s` in the regex stays load-bearing: `#hashtag` and `####### seven` are not
ATX headings and still render as prose. Headings inside a fence were never
affected, because the `inCode` branch precedes the heading check.

## Coverage

`tests/e2e/agent-markdown-render.e2e.json` had *pinned the old behaviour* one day
earlier (`stdoutAbsent: ["The plan"]`, and a leading blank row where the heading
had been), which is what made this a decision rather than a silent regression.
Both flipped: the block's first row is now `The plan`, and `## The plan` is the
absent needle — so the markers being stripped is pinned alongside the words
arriving. Boldness needed a third assertion: `stdoutBlock` strips SGR before
matching, so a future change to plain-but-stripped headings would have left it
green under a description claiming bold. A raw `\u001b[1mThe plan\u001b[22m`
needle in `stdoutContains` (which matches un-stripped output) closes that.
Five unit tests in `tests/cli/render/markdown-renderer.test.ts` cover
bold output, level-independence, the closing-`#` run, inline markup inside a
heading, the no-space non-headings, and `#` inside a fence.
