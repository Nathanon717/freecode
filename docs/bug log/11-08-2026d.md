# Background log lines painted over the input frame; a handled fallback dumped a stack to do it

**Files:** `src/logger.ts`, `src/cli/tui-log-sink.ts` (new), `src/index.ts`, `src/providers/provider-registry.ts`

At the interactive prompt, with a stale `SILICONFLOW_API_KEY`, the screen came apart a
second or two after launch — a timestamped error, its stack, and the footer divider all
shredded into each other on the input row:

```
──── models, using cache: HTTP 401054] [error] [registry] Failed to fetch siliconflow
Error: HTTP 401
4:5)at async getSelectableModels (file:///root/freecode/dist/commands/model.js:3
```

Two independent defects stacked.

**Cause 1 — every log write landed at the parked cursor.** `logError` wrote straight to
`process.stderr`, and nothing patches that stream. Mid-session the cursor is parked at the
typing caret *inside* the input frame (`drawInputArea`'s final `moveTo`), so an async write
starts painting there, over the frame and its dividers. Nothing about the registry is
special here: the startup model prefetch (`src/index.ts`, `getSelectableModels()` fired
detached) is just the one that reliably fires while a fresh prompt is on screen. The same
hazard covers ~30 `logError` sites, including every fire-and-forget DB persist.

**Cause 2 — a fully-handled fallback logged at error severity, with a stack.** The catch in
`runLiveProviderInit` has a complete answer (the cached catalog), and the throw it catches
is our own `new Error(\`HTTP ${res.status}\`)` from a few lines up, so the stack named
freecode's fetch wrapper and said nothing the message didn't. Screenfuls of noise for a
non-event.

**Fix:**

1. `logger.ts` gained `registerLogSink`; `log`/`logWarn`/`logError` all emit through it and
   fall back to raw stderr when none is registered, so headless and `-p` are untouched.
2. New `src/cli/tui-log-sink.ts`, registered by `src/index.ts` under the existing
   `process.stdin.isTTY` guard alongside the retry-banner and quota sinks. With the footer
   up it parks at the bottom of the scroll region, writes to stdout (the screen buffer
   records stdout only, so the line survives a resize repaint like any transcript line),
   normalizes `\n` to `\r\n` for raw mode, then repaints the chrome.
3. New `logWarn` — always-on like `logError`, one line, no stack — and the registry catch
   now uses it. Note this is *not* [10-08-2026c.md](10-08-2026c.md) returning: handled
   fallbacks still surface, they just surface as one line.

The sink skips its repaint while `isFooterTimerSuspended()` — new export, same guard the
footer timer already honours. A raw picker or the approval prompt manages those rows by
hand, and `/model` makes that overlap the common case rather than a corner one: opening the
picker is what fetches the model lists, so the registry's own log is likeliest to arrive
with the picker up. [10-08-2026d.md](10-08-2026d.md) is the same surface one day earlier —
stack traces scrolling the `/config` editor out of the viewport — fixed there by removing
the errors rather than fixing the channel, which is why the channel fix exists now.

**Verified** by driving the real TUI (`docs/pty-session.md`):

- Bogus `SILICONFLOW_API_KEY` at an idle prompt — reproduced the wreckage on the pre-fix
  build, then confirmed the post-fix build scrolls a single
  `[warn] [registry] … using cache: HTTP 401` line through the transcript, frame and both
  dividers intact.
- `FREECODE_NO_PREFETCH=1` so the fetch fires from `/model` instead — picker painted clean.
- Mid-turn, with a throwaway 1.5 s `logError` heartbeat patched into `dist/index.js`: every
  multi-line stack landed at column 1 in the scroll region while the `thinking…` label and
  the frame stayed put. `drawInputArea` takes its save/restore branch mid-turn, so the
  streaming cursor comes back to where the log line left it — pinned by a unit test rather
  than left to the probe.

**No e2e.** Triggering it needs a live provider fetch to fail, and the TTY harness sets
`FREECODE_NO_PREFETCH=1` precisely so e2e runs make no network calls
(`tests/harness/run-e2e.ts`). Covered instead by `tests/cli/tui-log-sink.test.ts` (park
sequence, stdout routing, CRLF, chrome repaint) and the `registerLogSink` cases in
`tests/logger.test.ts`.
