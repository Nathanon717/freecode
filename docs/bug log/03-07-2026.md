# No shared text-encoding layer — BOM and duplicated key-check bugs recurred every session

**Symptom:** The idea to fix this (`docs/ideas/we keep running into issues with st.txt`) had sat unbuilt since it was first captured. Concretely, two live instances were found while investigating:

1. `src/cli/session-modes.ts` had a real leading UTF-8 BOM checked into git — invisible in a normal editor/Read view, harmless to `tsc`/Node's module loader, but exactly the kind of stealth byte that forced ad hoc PowerShell hexdumps to diagnose in past sessions.
2. `\x7f`/`\x08` (backspace) detection was copy-pasted identically in `session-modes.ts`, `tool-approval.ts`, and `commands/model.ts`.

### Root cause

No shared place to route "read this file as text" or "is this key backspace" through, so every call site reimplemented it, and nothing repo-wide ever checked for a stray BOM. ~7 `readFileSync(path, 'utf-8')` / `JSON.parse(readFileSync(...))` call sites reading user-authored or downloaded files (config, AGENTS.md, eval prompts, humaneval dataset, tokenizer.json) were each one stray BOM away from `JSON.parse` throwing "Unexpected token" with no useful context — confirmed reproducible on this Node version.

Note: raw `0x7f` (DEL) bytes found in several `tests/scenarios/*.json` files are *not* a bug — they're legitimate literal keystroke data for backspace-simulating TTY scenarios, and JSON's grammar only forbids raw `0x00`–`0x1F`. The existing `tests/scenarios/scenario-json-bytes.test.ts` guard (added in an earlier session, see `docs/bug log/26-06-2026.md`) correctly excludes `0x7f` for this reason and was left unchanged.

### Fix

- New `src/util/text-encoding.ts`: `stripBom`, `readTextFile`, `readJsonFile`, `hasBom`. Applied at the call sites that read user-authored/edited/downloaded text: `src/config/index.ts`, `src/eval/custom.ts`, `src/eval/humaneval-data.ts`, `src/agent/system-prompt.ts`, `src/tokenizers/backends/bpe-json.ts`. Internal round-trip files this app both writes and reads back itself (model cache, quota cache, result sink, etc.) were left untouched — no external editor ever produces them, so there's no real BOM risk there.
- New `src/util/keys.ts`: `isBackspaceKey`, deduplicating the 3-way copy of the `\x7f`/`\x08` check.
- Stripped the live BOM from `src/cli/session-modes.ts`.
- New `tests/repo-encoding.test.ts` (repo-wide guard, `check-tests: orphan`): scans every `git ls-files`-tracked text file for a leading BOM and fails with the file name. This is the "once and for all" mechanism — it would have caught the `session-modes.ts` BOM before merge.
- `CLAUDE.md`/`AGENTS.md`: documented `readTextFile`/`readJsonFile` as the standard for reading externally-authored text, and a cross-platform `node -e` byte-inspection one-liner to replace ad hoc PowerShell/xxd hexdumps when checking whether a `\uXXXX` escape got mangled into a raw control byte during a tool-call write.

### Coverage

- `tests/util/text-encoding.test.ts`, `tests/util/keys.test.ts` (new unit tests).
- `tests/repo-encoding.test.ts` (new repo-wide BOM guard, part of the normal unit run).
- Full `npm test`: 92 files / 1707 tests passing, build+lint+docs+scenarios green.
