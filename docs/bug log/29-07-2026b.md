# 29-07-2026b — Two blank lines above a tool call on the fake path, one on replay

## Symptom

On the `mock:` (fixture) path, a step whose response text was followed by a tool
call painted *two* blank lines between them:

```
Reading both helpers.


Checking the type guard first
read(src/util/guards.ts)
```

`transcript-renderer.md` ("Desired Turn Layout") specifies one, and the replay of
the very same content — driven by the record through `renderTurn` — produced one.
So the live paint was the wrong side of the disagreement.

Found by the block assertions added in `cfc734a`: `tty-parallel-tools`' original
`transcriptBlock` pinned the buggy two-blank spacing, because it was authored from
a `TTY_DUMP` of the buggy screen.

## Cause

`providers/fake.ts` writes each step's chunks to stdout and then appends a
terminating newline (so a preamble does not glue onto the next step's text). It
records both. But `agent/fake-loop.ts` then told the step state machine about the
text with `notifyTranscriptChunk(generated.text)` — the model's *raw* text, which
does not include that appended newline.

`_step.textEndsWithNewline` therefore went false while the screen's cursor was
already at column 0 of a fresh line, and `writeTranscriptToolLeadIn` wrote its
"end the current line, then one blank" form `"\n\n"` instead of `"\n"`.

The replay path was correct for the opposite reason: the record holds what was
*written* (chunks + the newline), so `renderTurn` notifies with a
newline-terminated string and gets the documented single blank.

The native path was never affected — `createMarkdownStreamRenderer().push()`
returns each completed line with its `\n`, so `writeTranscriptText` notifies with
a newline-terminated chunk already.

## Fix

`FakeModelResult` gained `writtenText`: the text exactly as put on screen, chunks
and terminating newline included. `fake-loop.ts` notifies with that.

Re-deriving the newline rule at the call site was rejected — it would put the same
condition in two files, which is how the two drifted in the first place. Calling
`writeTranscriptText` from inside `fake.ts` was also rejected: `runFakeModel` is
shared with `subagents/run-subagent.ts`, and notifying there would fold sub-agent
chatter into the *parent* step's state.

## Coverage

`tests/e2e/tty-parallel-tools.e2e.json` — its `transcriptBlock` now pins the
single blank line. The block is the test: blank-line placement is the whole
contract and no substring check can see it.
