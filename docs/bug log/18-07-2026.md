# Scenario JSON file committed with a leading UTF-8 BOM

**Symptom:** `npm test` failed on `tests/repo-encoding.test.ts` —
`tests/scenarios/tty-tool-approval-preview-edit.scenario.json starts with a
UTF-8 BOM (EF BB BF) — strip it`. Everything else passed (1840/1841).

**Cause:** the scenario file was saved with a 3-byte BOM (`EF BB BF`) at offset 0.
The `repo-encoding` guard test forbids a leading BOM on tracked text files. The
BOM was harmless to the JSON parser, so the scenario itself ran fine — only the
encoding guard caught it.

**Fix:** stripped the first three bytes (`tail -c +4`), so the file now starts
with `{`. No content change.

**Coverage:** `tests/repo-encoding.test.ts` already asserts no BOM on tracked
files; it now passes.
