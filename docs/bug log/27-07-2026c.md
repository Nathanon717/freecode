# 27-07-2026c — `/config`, `/model` and `/eval` wiped the transcript **and its scrollback** while the conversation stayed live

## Symptom

Take a few turns, then open `/config` (or `/model`, or `/eval`) and leave it. The
screen is empty except for the banner, and scrolling up recovers nothing. The
session reads as fresh.

It is not. `Conversation.messages` is untouched, so the next turn resends the
entire history — the user is billed for and steered by a conversation with no
visible evidence on screen.

## Cause

`redrawBanner()` (`src/cli/render/banner.ts`) writes `\x1b[2J\x1b[3J` — erase
screen *plus* erase scrollback — and four commands call it:

| caller | screen | history |
|---|---|---|
| `/clear` (`command-dispatcher.ts`) | wiped | **also cleared** — coherent |
| `/config` (`commands/config.ts`) | wiped | intact |
| `/model` (`commands/model.ts`) | wiped | intact |
| `/eval` cancel (`cli/eval/eval-menu.ts`) | wiped | intact |

Only `/clear` calls `session.clearMessages()`; it is the single caller in the
tree. The other three inherited the same wipe without the matching clear, so
three of the four are incoherent. `\x1b[3J` is what makes it unrecoverable
rather than merely off-screen.

## Fix

Reprint the conversation after the wipe, from `Conversation.messages` — new
`src/cli/render/transcript-replay.ts`, called by the dispatcher after each of the
three commands. `/clear` is deliberately not called (its history is empty, so a
bare banner is accurate, and the replay no-ops on empty history anyway).

The dispatcher is the seam because it is also the only place that mutates
history, so the two can't drift.

**Rejected: repaint from the screen buffer.** The natural approach, and what the
resize handler in `cli/chrome/bottom-ui.ts` already does. It cannot work here.
The raw pickers' own cleanup writes `\x1b[${rowCount}A\r\x1b[J`
(`cli/menus/raw-picker.ts`), and `hasFullScreenErase` in
`util/screen-buffer.ts` matches `\x1b[J` — so the buffer is dropped before the
menu even returns. Rendering from `messages` also makes screen-matches-history
true by construction rather than by bookkeeping.

**Rejected: switch to `clearAndRedrawBanner()`** (which preserves scrollback).
Combined with the replay it would show the transcript twice.

## Related behavior change (not a bug fix)

Shipped alongside: tool calls and tool results now persist into history at all.
Previously `agentLoop` never mutated the caller's array and the dispatcher
appended only `result.text`, so a turn's tool calls and results were discarded at
the turn boundary — the model saw "user asked X, assistant said Y" with no record
that it had read six files to get there. See
`docs/map/agent/turn-messages.md`. That is what makes the replay's tool-call
lines meaningful, and it is why the replay omits result *bodies*: they are now
the bulk of a turn.

## Coverage

- `tests/e2e/tty-config-keeps-transcript.e2e.json` — takes a turn, opens and
  closes `/config`, asserts the marker text is back on screen; then `/clear` and
  asserts it is gone. Both directions, so a replay that fired unconditionally
  would fail the second half.
- `tests/e2e/agent-history-tool-turns.e2e.json` — covers the persistence change:
  a second user turn is sent 5 messages (create call + its result survive) where
  it was previously sent 3. Fails pre-fix with
  `expected 5 message(s), got 3`.

Note for multi-turn fixtures: `assertFakeFixtureComplete()` runs at the end of
**every** turn, so a fixture whose later steps belong to a later user turn needs
`"allowUnusedSteps": true` or turn 1 throws — and that throw lands in the fake
loop's catch, which returns no `turnMessages`, silently reverting to the
text-only fallback.

## Was still open — now fixed in [28-07-2026.md](28-07-2026.md)

Out of scope here: a turn whose `agentLoop` call throws left an orphan user
message in history (`command-dispatcher.ts` appended the user message before the
call and added no assistant message on the error path). Same for a turn whose
response is empty, which `addAssistantMessage` dropped by design. The dispatcher
now commits the user message and the turn's output together, or neither —
`Conversation.commitTurn`.
