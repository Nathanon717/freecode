# The map-drift sweep graded three criteria against content it was never sent

**Files:** `scripts/diagnostics/map-drift.ts`

`stripGeneratedBlocks` removes **every** `BEGIN/END GENERATED` block before a page
reaches the model — intent, exports, and facts alike. The sweep's system prompt
described the removal as "the page's generated blocks (auto-synced export
signatures)", i.e. only one of the three, and then listed among its drift criteria
"a stated purpose the file no longer has" and "'read when' guidance pointing at
behaviour that moved elsewhere".

Both criteria address sections the model cannot see. The page it receives is the
authored tail and nothing else, so those two rules could only ever produce a null
result — the sweep silently stopped auditing purpose and read-when drift while
still claiming to.

**Cause:** the prompt described the page shape as it stood before `@role` /
`@readwhen` moved into generated blocks (63b5f4d). The strip regex was always
`BEGIN GENERATED[\s\S]*?END GENERATED` — it did not change, so nothing broke
loudly; the prompt's description of it simply went stale underneath. The prompt
also still named "export notes" as a section a page carries, which the
export-notes migration has now deleted from all 55 pages that had one.

**Fix:** the prompt states that every generated block is stripped and names what
that covers, and the two unreachable criteria are gone. The page-shape line
describes what is actually generated and says the rest is the authored tail.

**Not fixed:** purpose and read-when drift now have no detector at all. Catching
it needs a check that reads `@role` / `@readwhen` from the source file rather than
from the page, since that is where they live — a different sweep, not a wider
prompt.

**Verified:** `npm test` green; the sweep's remaining three criteria all address
text the authored tail actually contains.
