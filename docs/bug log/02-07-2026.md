# PTY test harness: `send /` test flaky/failing on Windows

**File:** `tests/harness/pty/session.ts`

Two separate bugs in the PTY test harness, both surfaced by `send delivers keystrokes and returns updated screen` failing intermittently:

1. `resolveKey()` auto-appended Enter to any arg starting with `/`, including a bare `/`. A bare `/` is meant to just open the autocomplete suggestion list, not submit — `/\r` submitted an (invalid) empty command instead, resetting the prompt. Fixed by requiring `arg.length > 1` before auto-appending Enter (applied to both the positional-arg and stdin-pipe paths).

2. `runServer` marked the daemon ready as soon as the prompt text ("for commands") painted and output went quiet for 400ms. On Windows, ConPTY's raw-mode key handler isn't guaranteed live at that point — the very first keystroke sent right after `start` could be silently dropped (still in cooked/line mode), even though nothing about the visible screen indicated this. Confirmed via a `spawnSync`-based repro matching the test's own invocation: 0.7s of extra wait after start still failed 3/3, 1.5s passed 3/3, a single 1s try was borderline. Fixed by probing with a harmless space keystroke (clearing it afterward) until the empty-buffer placeholder disappears, before declaring the daemon ready — self-tuning instead of a fixed sleep.
