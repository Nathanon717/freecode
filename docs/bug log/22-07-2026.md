# Ghost input frame after a transcript-path resize (narrow)

**Symptom.** After a transcript is on screen (e.g. `/help` output), narrowing the
terminal left a **duplicate, stale copy of the input frame** in the scroll region: a
second `> / for commands` prompt with its own separator rules and footer, sitting
between the transcript and the real bottom bar. The stale rules were drawn at the *old*
width, so in the narrower terminal they wrapped — a full-width rule followed by a short
orphan remainder line.

**Why the 21-07 resize fix didn't cover it.** The 21-07-2026 Option-B fix (see
`14-07-2026.md`) branched on `hasPostEpochContent()`: fresh screen → `clearAndRedrawBanner`
(no stale cells); transcript showing → don't wipe, let the terminal reflow, and repaint
the scroll region from the screen buffer **only if a suggestion overlay was open**. Its
Resolution claimed the reflowed footer on the transcript path is "overwritten by transcript
flow rather than sitting alone." That held for the *fresh-session* height-grow / width-shrink
cases it was verified against, but **not** for narrowing while a transcript is up: the
cursor-addressed bottom UI reflows into the scroll region as a wrapped ghost, and with no
overlay the scrub never ran, so nothing erased it.

**Root cause.** The bottom UI is drawn with absolute cursor positioning into rows outside
the scroll region and is **not** in the screen buffer. Native SIGWINCH reflow drags those
cells into the scroll region as stale duplicates. Erasing them requires repainting the
scroll region from the clean transcript buffer — the same move the overlay case already
made, just gated too narrowly (`hadOverlay && !menu`).

**Fix.**
- `src/cli/chrome/bottom-ui.ts`: run the scroll-region repaint on **every** transcript-path
  resize (`_onResizeCallback === null`), not just when an overlay was open. This erases the
  ghost input frame wherever it landed and bottom-aligns the transcript above the input bar.
- `src/util/screen-buffer.ts`: the old scrub **truncated** over-wide buffer lines at `width`
  (fine for short overlay rows, lossy for real transcript lines). Added `wrapStyledToRows`
  (ANSI-aware: carries open SGR across the break, closes it at each row end) and made
  `getScreenBufferScrollRegionLines(rowCount, width)` wrap over-wide logical lines into exact
  display rows first. The repaint now preserves long lines by wrapping instead of clipping.

The banner is pre-epoch and excluded from the buffer, so it is dropped on a transcript-path
resize — but the pre-fix native reflow scrolled it off anyway, so this is not a regression.

**Coverage.**
- New `screenCounts` primitive in the TTY harness (`run-tty-scenario.ts`): assert a substring
  appears an exact number of times. This is what finally makes the ghost expressible in a
  scenario — the wrapped-dash remnant is substring-indistinguishable from a real rule, but the
  duplicate `> / for commands` is a count of 2 vs 1.
- `tty-resize-preserves-transcript` narrow step now asserts `"> / for commands"` appears
  exactly once. Verified reproduce-before-fix: fails on baseline (`2×`), passes with the fix.
- `screen-buffer.test.ts`: unit tests for `wrapStyledToRows` and the wrapping path of
  `getScreenBufferScrollRegionLines`.
