# The `.git` guard was case-sensitive on case-insensitive filesystems: `create .GIT/hooks/pre-commit` wrote the real hook

**Files:** `src/agent/tools/git-guard.ts`

`git-guard.ts` exists to make one guarantee: an agent cannot write into a
project's `.git`. Its own header says why the gap is closed by prevention rather
than backup — snapshots restore worktree content, not the user's object store,
and `shell_exec`'s `confirmDestructive` is a parameter the *model* sets, forced
to `auto` under `freecode -p --edit`, so nothing downstream intercepts.

Every spelling of the path that Windows and macOS resolve to `.git` walked
straight past it:

```
create   .GIT/hooks/pre-commit    -> written
shell_exec  echo x > .Git/config  -> allowed
```

Demonstrated against built code, not inferred — a planted `pre-commit` hook
actually executed during a subsequent `git commit` in the test project.

**Cause:** all three checks compared bytes, on filesystems that do not.

```ts
const GIT_INTERNALS = /(?:^|[\s'"=`(/\\])\.git(?![\w-])/;      // no /i
const REDIRECT_INTO_GIT = /…\.git(?![\w-])/;                   // no /i
segment === '.git'                                             // exact
```

NTFS and APFS open `.GIT/hooks/pre-commit` as `.git/hooks/pre-commit`. The guard
refused the lowercase spelling and permitted the uppercase one, for the same
file.

**Fix:** `/i` on both regexes and `segment.toLowerCase() === '.git'` in
`isGitInternalPath`. On Linux `.GIT` really is a different directory, so this is
a false positive there — an acceptable one, since nothing legitimate writes to a
path spelled that way, and the alternative is a platform-conditional guard.

**Not fixed here, and worse:** this is a denylist over an unbounded shell, and
case was only the cheapest bypass. `git config core.hooksPath` gives the same
RCE while never containing the string `.git` at all, as do `git reflog expire`,
`gc --prune=now`, and `branch -D`. Those are defeated by git itself, not by
spelling, and no regex closes them. The audit's conclusion stands: the guard
buys time, not safety, and is retired by snapshotting `.git` and by containment
— neither of which is implemented yet, so nothing here should be read as
`.git` being protected.
