# 28-07-2026 — A turn that produced nothing still committed the user's message (and a failed one committed the error as the assistant's own words)

## Symptom

Two shapes of the same defect, both confirmed live before fixing.

**Aborted turn.** Send a message, let the model call a tool, press Esc at the
approval prompt. `(empty response from model)` prints and the prompt returns.
History is now `[user]` with no assistant turn. Driven through `pty` with a fake
fixture, the next turn's trace read:

```
{ call: 1, msgs: 1, lastUser: 'make a note' }
{ call: 2, msgs: 2, lastUser: 'second message' }   ← [user, user]
```

**Failed turn.** Same setup, provider error instead. The next turn was sent 3
messages: the orphan, *plus* the error report persisted as an assistant message —
so the model saw itself having said
`Error: Context window exceeded — run /clear…`. On context overflow that
compounds: the poisoned history makes the retry overflow too.

Consecutive user messages are legal (see `conversation.ts`), so nothing 400s. The
harm is quieter — dead turns accumulate, are resent and paid for on every later
request, and present the model with a request it never answered.

## Cause

`sendToAgent` (`cli/command-dispatcher.ts`) appended the user message *before* the
work, and no path removed it:

```ts
runtime.session.addUserMessage(input);   // committed unconditionally
await runtime.beforeAgentCall?.();
try {
  const result = await agentLoop(runtime.session.messages, …);
  if (!runtime.session.addTurnMessages(result.turnMessages)) {
    runtime.session.addAssistantMessage(result.text);   // drops blanks
  }
} catch (error) { /* prints, adds nothing */ }
```

Three routes reached it:

1. **Abort.** `UserAbortError` comes from `cli/tools/tool-approval.ts` — Esc at a
   tool approval, the only source. `agentLoop` catches it and returns
   `finishResult(fullText)`: no `turnMessages` (they are collected only from a
   drained stream), and `fullText` empty when the model called the tool without a
   preamble. The fallback then called `addAssistantMessage('')`, which the
   empty-assistant guard drops **by design** — that guard is right, see
   [18-07-2026b.md](18-07-2026b.md).
2. **`agentLoop` throws.** The catch prints and appends nothing.
3. **`beforeAgentCall()` throws.** It sat *outside* the try, so it escaped
   `sendToAgent` entirely and `afterAgentCall` never ran either — the same shape,
   plus a bottom UI torn down with nothing to rebuild it.

Route 2 is also the rarest: in the common failure `agentLoop` does not throw at
all. It catches internally and returned the error folded into `result.text`
(`fullText + '\n\nError: …'`), which the fallback dutifully persisted.

## Fix

**The session is only ever mutated with a complete turn.** The user message is no
longer appended up front; it rides along on a copy for the duration of the turn
and is committed with the turn's output or not at all:

```ts
const userMessage: CoreMessage = { role: 'user', content: input };
const turnInput = [...runtime.session.messages, userMessage];
const result = await agentLoop(turnInput, …);
runtime.session.commitTurn(userMessage, result.turnMessages, result.text);
```

The same object goes to the model and into history, so the two cannot drift.

`Conversation.commitTurn` replaces `addUserMessage`/`addAssistantMessage`/
`addTurnMessages` (all three had no other caller). It sanitizes first and decides
emptiness *from the sanitized tail* — a turn whose only content was an unpaired
tool call is nothing, not a reason to strand the user message — then pushes the
user message and the tail together, or neither. This fits the invariant the
`turnMessages` work already established (see
[27-07-2026c.md](27-07-2026c.md), whose "Still open" this closes); it works
because `agentLoop` reads its `messages` argument and never mutates it.

Partial output still counts: a turn that emitted text and *then* failed commits
the user message plus that text. Only a turn that produced literally nothing
leaves history untouched.

**`AgentLoopResult` gained `error?: string`.** `text` is now the model's own
output and nothing else; the failure message travels separately (it was already
printed to stdout by the loop that raised it). Four sites emitted the baked-in
suffix — `loop.ts`'s stream catch, `FREECODE_NO_LLM`, the `resolveModel` failure,
and `fake-loop.ts` — and all four now set `error` instead. The dispatcher needs
this signal anyway: once failures stop being committed, `"Error:"` embedded in
prose is no way to know a turn failed. `(empty response from model)` is
correspondingly gated on `!result.error`, so an error turn no longer prints both.

`beforeAgentCall()` moved inside the try, so a throw there is reported and
`afterAgentCall` still restores the input bar.

**Rejected: pop the user message back off on failure.** Simpler, but it leaves a
window where history is inconsistent and it has to know exactly what was
appended — including whatever a partially-committed turn already pushed.

## Coverage

- `tests/e2e/agent-turn-failure-no-orphan.e2e.json` — fixture errors on turn 1;
  turn 2 asserts `inputMessageCount: 1` and the fixture's own `messageCount: 1`
  matcher says the same thing independently. Pre-fix: `expected 1, got 0` calls
  and no `second turn ok`.
- `tests/e2e/tty-abort-no-orphan.e2e.json` — the live abort: tool call with no
  preamble, Esc at the approval, then a second turn. The history assertion is the
  fixture's `messageCount: 1`; the *observable* is `second turn ok` reaching the
  screen, because a fixture mismatch throws into the fake loop's catch and prints
  an error instead of the reply. Pre-fix: `waitFor not seen: "second turn ok"`.
- `tests/agent/conversation.test.ts` — `commitTurn` all-or-nothing, including the
  sanitize-then-decide case (unpaired tool call commits nothing).
- `tests/cli/command-dispatcher.test.ts` — now drives a real `Conversation`, so
  the assertions are about the history a turn leaves behind: untouched on abort,
  on error-before-output, and on a throw; user + partial text when the model spoke
  before failing; the error never persisted; and `beforeAgentCall` throwing now
  recovering through `afterAgentCall`.

## Note for multi-turn fixtures

Both new fixtures set `"allowUnusedSteps": true` — `assertFakeFixtureComplete()`
runs at the end of **every** turn, and its throw lands in the fake loop's catch,
which silently reverts to the text-only path.
