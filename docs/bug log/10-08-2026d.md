# Every write on a local-only install threw `SyncNotSupported("File")` — `sync()` was called whether or not the client was a replica

**Files:** `src/store/db.ts`, `src/store/db-replica.ts` (new), `tests/store/db-replica.test.ts` (new)

Found immediately after [10-08-2026c.md](10-08-2026c.md) removed the `logError` gate.
This is the first error the ungated logger surfaced, and it had been thrown on every
single write for as long as the gate was in place.

`openAndPrepareClient` opens one of two very different clients:

- no `syncUrl`/`authToken` → `createClient({ url })`, a plain local file with no remote
- both present → `openSyncedClient(...)`, a libSQL embedded replica

But all five write paths — model upsert, catalog upsert, call-log insert, config
upsert, transcript insert — ended with an unconditional

```ts
await c.sync().catch((err) => logError('db', 'sync after … failed', err));
```

On a plain local-file client there is nothing to push and libSQL throws
`SyncNotSupported("File")`. So on a local-only install (no Turso configured — the
default) *every* persisted write raised, was caught, handed to `logError`, and
dropped on the floor by the gate. The `.catch()` meant the write itself still
succeeded, which is why nothing ever looked broken.

## How it surfaced

With the gate off, the errors went to stderr — and in the TUI stderr and stdout share
one PTY, so two stack traces scrolled the `/config` editor off screen mid-session.
`tty-config-toggle` failed on `screen missing: "Tool rationale"`, which looked like a
rendering regression. It wasn't: the toggle rendered correctly and was then pushed out
of the viewport by the error text. A PTY probe capturing raw bytes after the space
keypress showed the editor drawn correctly, followed by the traces.

Worth noting how the failure presented — a screen assertion in an unrelated TTY test,
naming a UI string, for a store bug two layers down.

## Fix

`syncReplica(c, what)` replaces the five bare `c.sync()` calls and no-ops unless the
open client is actually a replica, tracked by a `clientIsSynced` flag set where the
client is chosen and cleared everywhere it is torn down. The synced-path `sync()`
calls in `openAndPrepareClient` and the primary-delete path are unchanged — those are
already inside a `syncUrl && authToken` branch.

`db.ts` went 10 lines over the 500-line limit, so the four pure replica helpers
(`wipeLocalDb`, `isReplicaConflict`, `isSyncReplica`, `DB_FILE_SUFFIXES`) moved to
`db-replica.ts` with their tests. They hold no client state, so nothing had to be
rewired — `syncReplica` and `openSyncedClient` stay in `db.ts` next to the state they
read.

## Note

A `.catch()` that logs is not error handling when the logger is allowed to be silent.
The two defects composed: one made writes throw, the other made the throw invisible,
and each alone would have been caught in a day.
