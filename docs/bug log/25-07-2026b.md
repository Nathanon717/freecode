# Bug Log

## Turns ended mid-task at 10 tool steps, reported as "(empty response from model)"

**Symptom:** while the agent was working through a task and calling tools, the
turn would stop and print yellow `(empty response from model)`, ending the
agent's turn with the task unfinished.

**Cause:** `src/agent/loop.ts` passed `maxSteps: 10` to `streamText`. Once the
model had made 10 tool round trips the AI SDK stopped the turn even though the
model was still calling tools. The parsed-tools fallback
(`src/agent/parsed-tools.ts`) had the same cap as a hardcoded
`for (let step = 0; step < 10; step++)`, and `runFakeLlm` a third copy.

The cap was invisible at the point it bit. The dispatcher's message at
`src/cli/command-dispatcher.ts:116` fires whenever `result.text` is empty and
cannot tell *why* — so budget exhaustion surfaced under the same wording as a
genuinely empty provider response.

**Fix:** removed the per-turn step limit from all three loops.

- `loop.ts`: `maxSteps: Number.MAX_SAFE_INTEGER`. Note this cannot be expressed
  by omitting the option — the AI SDK defaults `maxSteps` to `1`
  (`node_modules/ai/dist/index.mjs:4024`) and only ever reads it as
  `currentStep + 1 < maxSteps`, so dropping it would have made the truncation
  far worse rather than removing it.
- `parsed-tools.ts` and `runFakeLlm`: `for (let step = 0; ; step++)`.
- Removed the now-dead post-loop `endTranscriptStep(false)` in `parsed-tools.ts`
  (the no-tool-calls `break` is the only normal exit and already closes the
  step) and the unreachable `Fake LLM fixture exceeded max tool steps (10)`
  throw. The fake loop still terminates on its own: `runFakeModel` throws once
  the fixture runs out of steps.

A turn now ends when the model stops calling tools, the context window
overflows (already handled by `isContextOverflowError`), the provider errors, or
the user aborts.

**Caveat:** with no step ceiling, a model that loops on tool calls will keep
going until it overflows the context or the user hits ESC. Scripted/eval runs are
unaffected — they are bounded by the separate `FREECODE_MAX_TOOL_CALLS` budget in
`src/cli/session-modes.ts`, not by `maxSteps`.

**Not addressed:** `(empty response from model)` is still printed purely on empty
text, so it remains ambiguous between a provider returning nothing and a silently
aborted turn (`loop.ts`, the `isUserAbortError` early return prints nothing).
Whether the original reports were step exhaustion or one of those was never
confirmed from a `-log` capture — the cap was removed on request.

**Coverage:** none added; the change only removes limits. Sub-agent personas keep
their own `maxSteps` in `src/agent/subagents/registry.ts` (Explore: 16) — those
are delegated helper budgets and were left alone.
