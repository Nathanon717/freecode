# `checkpoint revert` from a subdirectory could not find its snapshot on Windows

**Files:** `src/cli/checkpoint-root.ts` (new), `src/cli/checkpoint.ts`

`freecode checkpoint revert` run below the launch directory returned exit 0 but
left the damaged file in place. Snapshot discovery asked Git for
`--show-toplevel`, then bounded its upward walk by comparing that result with the
caller's path.

On Windows the two strings can name the same directory differently: Node's
`tmpdir()` supplied an 8.3 path containing `NATHAN~1`, while Git expanded it to the
long user-directory spelling. `path.relative` therefore classified the launch
directory as outside its own repository before discovery reached the project root.
The command fell into its ordinary "no snapshots here" path, whose exit 0 made the
miss look like a successful revert.

**Fix:** derive the repository ceiling with `git rev-parse --show-cdup` and resolve
that relative route from the caller's original `startDir`. The path spelling now
stays identical to the spelling used to key the snapshot store, while the walk
remains bounded by the enclosing repository. Snapshot-root discovery moved to its
own module because `checkpoint.ts` was already at the 500-line budget.

The existing CLI regression now passes on the short-path Windows temp directory,
and a mirrored unit test pins discovery itself. The full unit suite passes: 149
files, 3,623 tests passed, one skipped.
