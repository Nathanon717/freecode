# `logError` swallowed every error unless `-log` was passed — a test-coverage commit reverted the fix that made errors unconditional

**Files:** `src/logger.ts`, `tests/logger.test.ts`

Found by the `intent-drift` sweep, which flagged `@role`'s "errors always surface"
against a `logError` body that opened with `if (!enabled) return;`.

The contradiction was four-way, not two-way, which is why it read as a doc typo:

| Says errors always print | Says errors are gated |
| --- | --- |
| `@role` "errors always surface" | the `if (!enabled) return;` in `logError` |
| `logError`'s JSDoc "Always writes to stderr regardless of `enableLog` state" | `@readwhen` "enableLog() gates every write" |
| | `tests/logger.test.ts` "is silent when not enabled" |

Three statements against two is the wrong way to count. History settles it:

- `dd5c413` ("Surface swallowed errors") **deliberately deleted** that line, and said
  so in its own message: *"Make `logError` always write to stderr regardless of the
  `enabled` flag, so errors surface even when file logging is off."* The same commit
  replaced bare `catch {}` blocks with `logError(...)` across tools, the eval
  pipeline, and the provider registry — the gate's removal was the entire point of
  those call sites.
- `7f4b36c` ("Add unit test coverage and eval results"), three days later, re-added
  the one line as an unmentioned "supporting logger code" change. A one-line silent
  revert inside a large test-coverage diff.
- `b46643a` then added `it('is silent when not enabled')`, codifying the regression
  as the intended contract. From that point the behavior was pinned by a green test,
  which is why it survived until a sweep read the prose instead of the tests.

So every `logError` call added by `dd5c413` specifically to stop swallowing errors
had been silently swallowing them again ever since — config load failures, blocklist
read/write failures, eval result-sink write failures, tool trace failures, and
`resolveModel`/`streamText` failures all vanished unless the user happened to pass
`-log`.

The first error the ungated logger surfaced was a real, live defect — `sync()` called
on a plain local-file client, throwing on every write since the gate went in. See
[10-08-2026d.md](10-08-2026d.md). That is the argument for the gate mattering: it was
not hiding noise.

## Fix

Removed the gate from `logError`. `log()` keeps its gate — that is the `-log` flag's
actual job. The `@readwhen` bullet now draws the distinction instead of flattening it
("gates log() — but never logError()"), and the test asserts the real contract.

## Note

A doc/code contradiction where the *tests* side with the code is not evidence the
docs are wrong. A test written after a regression documents the regression. Reach for
`git log -S` on the contested line before deciding which side is the defect — here it
named the commit that removed the line, the commit that put it back, and the fact
that only one of them mentioned doing so.
