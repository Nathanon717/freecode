# The map's page-shape contract called the H1 generated; nothing generates it

**Files:** `docs/map/README.md`, `scripts/checks/check-map.ts`

The § Page shape block labelled every line of a page's head, and the first was
`# src/agent/loop.ts — Agent Loop     GENERATED  (path + @role title)`.

No generator writes that line. `renderIntentBlock` produces `## Role` and
`## Read When`; `upsertIntentBlock` only *finds* the H1 and splices its block
below it. The traffic runs the other way — `buildStructureBlock` reads each
page's H1 through `pageLabel()` to title the entry in the README's structure
tree.

So the one line that names which source file a page is about was authored, was
described to every agent as machine-maintained, and was checked by nothing. A
renamed or moved source file would leave a stale path in the H1 and the same
stale label in the structure tree, and `docs:generate` would keep regenerating
the tree *from* the stale value.

**Cause:** the label was true of an earlier plan for the head, not of what
shipped. Nothing failed when it stopped being true, because a claim about who
maintains a line has no test.

**Fix:** the line reads `AUTHORED (source path + a short label)`, and
`check-map.ts` now enforces what was previously only asserted: a page's H1 must
start with its own source path and carry a non-empty label after it. The corpus
passed on the first run, which is why this cost nothing to close — it was a
latent trap, not an outage.

**Verified:** `npm test` green. The check was exercised against a page with a
mangled H1 before being trusted against a corpus that passes.
