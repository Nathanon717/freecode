# 12-08-2026 — `npm run map` rejected source paths on its glob verbs

## Symptom

The workflow CLAUDE.md prescribes — inspect `git diff --name-only`, then query the map for
what you touched — failed on the paths `git diff` actually prints:

```
$ npm run map -- role src/agent/
No map page matches src/agent/.
$ npm run map -- role src/agent/loop.ts
No map page matches src/agent/loop.ts.
```

The same spellings worked on `exports`, `sections` and `neighbors-of`, so the failure looked
like a typo rather than a verb-dependent rule.

## Cause

The two selectors were written independently and never reconciled. `normalizeMapPath`
(`scripts/docgen/map-sections.ts`) strips a leading `src/` and rewrites `.ts` to `.md`;
`matchesGlob` stripped only `docs/map/` and treated any wildcard-free pattern not ending in
`.md` as a *directory prefix*. So `src/agent/loop.ts` became the glob `src/agent/loop.ts/**`,
which matches nothing — and the error said "no page matches", not "that spelling is only
accepted by some verbs".

File verbs took three spellings; glob verbs took one. They overlapped only on `agent/loop.md`.

## Fix

`matchesGlob` now normalizes the same two source spellings before applying glob rules: strip a
leading `src/`, rewrite a trailing `.ts` to `.md`. Ordering matters — both run *before* the
directory-prefix rule, so `src/agent/loop.ts` resolves to the literal page `agent/loop.md`
instead of widening into a prefix, while `src/agent/` still becomes `agent/**`. Wildcards
survive the rewrite, so `src/agent/*.ts` works too.

The strip is unambiguous: `docs/map/` has no `src` entry, because pages mirror `src/**` at
identical depth — the map root already *is* `src/`.

## Guard

`tests/scripts/map-query.test.ts` covers the accepted spellings and, separately, that a source
spelling does not widen past its own directory (`src/agent/loop.ts` must not match
`agent/fake-loop.md`) — the regression the prefix rule would reintroduce.

## Not fixed

`exports` still takes a single file where `section Exports <glob>` fans out. That overlap is
deliberate: `exports` omits the per-page header, which is what makes one page's signatures
pasteable. Globbing it would need a conditional header and would then duplicate `section`.
