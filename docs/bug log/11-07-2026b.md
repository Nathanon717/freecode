# Bug Log

## Startup banner reappears mid-screen when slash-command suggestions shrink

**Symptom:** Type `/` to show the slash-command list, then type letters to filter
it. As the list shrinks, the rows the longer list had covered are revealed — but
they're repainted with fragments of the **startup banner** instead of the
transcript. Persisted across several prior fixes, including the "big" one that
introduced the overlay epoch.

### Root cause

The slash-suggestion overlay repaints the rows it temporarily covered from a
*model* of stdout, not the real screen: `screen-buffer.ts` keeps a styled rolling
buffer of written lines, and `getScreenBufferDisplayLinesForOverlay` slices it from
`epochStart` onward. The epoch exists precisely to exclude the banner (chrome) from
those repaints.

The prior fix set the epoch **once**, on the first `setupInputUI`. But the banner
is reprinted mid-session by `/clear`, `/model`, `/config`, `/eval`
(`redrawBanner`) and by resize (`clearAndRedrawBanner`). Each does
`console.log(banner)`, whose color-only text (no cursor/screen control) is captured
by the buffer and appended **after** `epochStart`. So the banner landed inside the
overlay epoch, and `getScreenBufferDisplayLinesForOverlay` handed banner lines back
as "restore content." When the suggestion list shrank, the overlay repaint painted
the banner onto the revealed rows.

Confirmed with a direct unit probe: after `startOverlayEpoch()`, simulating a
banner redraw (full-screen erase + `console.log(banner)`) made
`getScreenBufferDisplayLinesForOverlay` return the banner text.

### Fix

Treat the epoch as *per screen-clear*, not once-ever, so the banner is always
chrome:

- `src/util/screen-buffer.ts`: a write containing a full-screen / scrollback erase
  (`\x1b[…J`, e.g. the `\x1b[2J` in `clearEntireTerminal`/`clearAndRedrawBanner`)
  now resets all buffers and the epoch — nothing previously on screen can sit
  behind an overlay after the screen is wiped. Line erase (`\x1b[2K`) is unaffected.
  Only `banner.ts` ever emits a full-screen erase, so this fires solely on banner
  redraws.
- `src/cli/banner.ts`: `showBanner`, `redrawBanner`, and `clearAndRedrawBanner` now
  call `startOverlayEpoch()` right after printing the banner, re-marking the epoch
  past the freshly drawn banner on every redraw (the once-only `setupInputUI` call
  no longer suffices because it doesn't re-run when the banner is reprinted).

### Coverage

`tests/util/screen-buffer.test.ts` gains a "full-screen erase resets the overlay
model" block: a redrawn banner (erase + banner print + `startOverlayEpoch`) no
longer leaks into `getScreenBufferDisplayLinesForOverlay`, while transcript printed
*after* the banner is still restorable. Both failed before the fix.
