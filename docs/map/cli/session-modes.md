## Interactive Mode

- Uses raw stdin for prompt input via `runRawKeySession` (from `cli/menus/raw-picker.ts`), which owns the listener snapshot/restore and raw-mode lifecycle. This prevents readline from echoing typed characters into `process.stdout` and contaminating the screen-buffer epoch used by the suggestion overlay restore.
- Supports Ctrl+C exit, Enter (`\r`) submit, Tab completion, Backspace, Delete, Escape clear, printable character input, and Ctrl+letter shortcuts for footer toggles (Ctrl+A = Ask, Ctrl+R = Read-only).
- Ctrl+J (`\n`) inserts a newline, enabling multi-line input. Arrow keys (Left/Right/Up/Down), Home, and End move the cursor within the buffer; Delete removes the character at the cursor.
- Printable input goes through `handlePrintable`: typing `(` right after a valid tool name (see `cli/tools/tool-invocation.ts`) autofills the full argument skeleton (`read(path="", offset=, limit=)`) with the caret in the first value slot; typing `)` on top of a `)` types over it. Tab cycles forward through the value slots and Backspace at an emptied slot steps back (via `nextToolFieldCaret` / `toolFieldBackspace`); on submit `stripEmptyToolArgs` drops untouched slots.
- Shows inline command completion plus filtered suggestions from `slash-commands.ts`. Inline completion is suppressed for multi-line buffers.
- Starts an OpenAI-only preflight input-cost controller while editing, debounced from input changes and stopped on submit/cancel/teardown.
- Refreshes cached OpenAI daily spend snapshots for the footer when the bottom UI is active and the selected model is OpenAI.
- **Owns the footer `ctx` (context size) slot** — the *only* writer. `onAgentResult` reads `result.usage.promptTokens` (the provider-reported input tokens of the turn's last call = the whole history it resent) and passes it to `setContextUsage`, looking the model's `contextWindow` up via `providers/model-data.ts` `getModel`. Skips the update when no count was reported (a turn that errored before usage keeps the last good number). For `providerId === 'anthropic'` it forces `setContextUsage(null)` — Anthropic's `input_tokens` excludes `cache_read`/`cache_creation`, so the count reads far low once caching kicks in; a blank slot beats a confident undercount until `usage-finalize.ts` sums the cache fields. `applyModelChange` also blanks it so a stale count is never attributed to a newly-selected model. See `cli/chrome/footer-status.ts`.
- **The `ctx` slot ticks up mid-turn.** `onStepUsage` (a `session-runner`/`command-dispatcher` hook fed by `agent/loop.ts`) fires at every step boundary of a multi-step tool turn with that step's own prompt tokens, so the count climbs while the agent is still working instead of jumping once at the end — each step resends a longer history, and the last value equals what `onAgentResult` would set. Both handlers share the `applyContextUsage` helper. Two details worth keeping: it calls `drawFooter()` directly rather than waiting on the footer's 1 s refresh timer (a step that completes inside that second would otherwise never be shown), and for Anthropic it **skips** the update rather than blanking, leaving `onAgentResult`'s `setContextUsage(null)` in charge instead of clearing the slot on every step. This works at all only because `teardownBottomUI` drops just the input area — the footer stays live for the whole turn. Note the count is *hidden* while a tool-approval prompt is up: `cli/tools/tool-approval.ts` deliberately blanks the footer rows so the confirm hint owns the last row. Covered by `tests/e2e/tty-status-line-ticks.e2e.json` (auto-confirm + a sleeping `shell_exec`, so the intermediate value is observable without a timing race).
- Tears down the bottom UI during command dispatch, agent output, and tool approval prompts. The config editor and model picker manage their own teardown/restore via `cli/menus/menu-shell.ts`; the dispatcher's `runConfig`/`runModelMenu` are now thin calls that pass an `onRestore` closure (session footer refresh — `applyModelChange`/`resetBottomPromptState`/`refreshFooterDailySpend`/`drawBottomUI`) into `runConfigCommand`/`runModelCommand` for the shell to fire after `setupBottomUI`.
- `/model` without an argument opens `runModelCommand()` so interactive users can pick from configured provider models and detected Ollama models.
- Tool approval uses a two-item Approve/Deny menu; denial can include user feedback to the agent. The Auto-run tools toggle (`getAskMode()` from `cli/chrome/toggles.ts`) controls whether approval is required at runtime; the initial state is seeded from `config.toolConfirmation`. The approval prompts and the scripted-choice parser live in `cli/tools/tool-approval.ts`; both modes import them. For precomputed read-only tools (which carry `preview.resultText`) interactive mode hands `confirmToolCallInteractive` a **thunk** `() => countTextTokens(resultText, getSelectedModel())` (from `tokenizers/count.ts`) for the hint's "+N tokens" / "+N tokens appx" line; the UI evaluates it on a deferred tick so the first (tokenizer-compiling) count can't stall the confirm controls. Model selection (`applyModelStatus`/`applyModelChange` → `warmTokenizers`) fires `preloadTokenizerFor(model)` on a timer so the count becomes exact once the model's tokenizer is compiled — deferred, and a no-op for models with no exact backend, so it never freezes startup. Interactive mode has no per-turn tool-call cap (the agent loop's `maxSteps` bounds each turn); scripted mode enforces a hard `FREECODE_MAX_TOOL_CALLS` budget by silently denying every call past the cap.
- **Auto-approve token budget.** When `resolveModelSettings(model).autoApproveTokenBudget` is `> 0`, a tool call whose token count is strictly under it is approved without a prompt even in Ask mode. Gated by an explicit `BUDGET_APPROVABLE_TOOLS` allowlist (`read`, `grep`, `list_dir`) — deliberately *not* "any tool we can count", so it can never widen implicitly; `create` has a content preview and is measurable but writes a file, so it is never auto-approved at any budget. The comparison calls the same `getTokenCount()` thunk the hint would have displayed, so the number the user configures against is the number they would have seen (fallback estimate included). `0` is off.
- The Read-only toggle (`isReadOnly()` from `cli/chrome/toggles.ts`) is passed as `getReadOnly` on the mode object. When on, only `read`, `grep`, and `list_dir` are offered to the model (write/edit/shell are omitted from `createTools`).
